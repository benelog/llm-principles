# 추론 서빙의 비용 구조 측정

Go 표준 라이브러리만으로 만든 작은 트랜스포머(4층, 임베딩 64차원)로
프로덕션 추론 서빙의 비용 구조를 측정하는 예제다. 학습은 하지 않고
무작위 가중치를 쓴다. 계산량과 메모리 크기는 가중치 값과 무관하므로
시간과 용량을 재는 데는 지장이 없다.

세 가지를 측정한다.

1. **프리필의 병렬성**: 프롬프트 토큰들을 한 토큰씩 순차 처리할 때와
   위치들을 병렬 처리할 때의 시간 비교. 같은 결과가 나오는지도 검증한다.
2. **KV 캐시의 효과**: 캐시를 쓰는 생성과, 토큰마다 시퀀스 전체를
   다시 계산하는 생성의 시간 비교. 두 방식이 같은 토큰 열을 내는지 검증한다.
3. **KV 캐시의 메모리 크기**: 이 예제 모델과 Llama 3 8B급 설정에서
   컨텍스트 길이에 따른 캐시 크기 계산. GQA의 절감 효과도 확인한다.

## 실행 방법

```bash
go run .
```

외부 모듈 의존성이 없으므로 Go만 설치되어 있으면 바로 실행된다.
전체 실행에 10초 안팎이 걸리는데, 대부분 "캐시 없음" 생성의 시간이다.
시간 수치는 실행하는 기계에 따라 달라지지만 배율의 규모는 유지된다.

## 실행 결과 예시

```
모델: 4층, 임베딩 64, 헤드 8개 | 프롬프트 256토큰, 생성 64토큰, CPU 코어 8개

== 프리필: 프롬프트 처리 ==
한 토큰씩 순차 처리:   125.6ms
위치들을 병렬 처리:     32.7ms (3.8배)
두 방식의 마지막 은닉 벡터 일치: true

== 디코드: 토큰 생성 ==
KV 캐시 사용:    61.9ms (토큰당 970µs)
캐시 없음:      9.9446s (토큰당 155.38ms, 161배)
두 방식의 생성 결과 일치: true

== KV 캐시 크기 ==
이 예제 모델 (4층, 헤드 8개, 컨텍스트 512, float64): 2.0 MiB
Llama 3 8B (32층, KV 헤드 8개, 헤드 차원 128, FP16):
  컨텍스트    8192 토큰: 1.0 GiB
  컨텍스트  131072 토큰: 16.0 GiB
GQA 없이 KV 헤드 32개라면, 컨텍스트 131072 토큰: 64.0 GiB
```
