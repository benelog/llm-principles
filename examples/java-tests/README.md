# java-tests: 순수 자바 예제의 JUnit 테스트

`examples/java/` 아래 여섯 예제의 주요 클래스가 각각 어떤 역할을 하는지 확인하는 JUnit 5 테스트다. 예제 소스는 그대로 두고(빌드 파일 없이 `java Main.java`로 실행하는 원칙을 지킨다), 이 디렉터리의 Gradle 프로젝트가 예제 디렉터리를 소스 경로로 가리켜 컴파일한다. 검증문은 읽기 쉽도록 AssertJ를 쓴다.

```bash
cd examples/java-tests
./gradlew test
```

특정 예제만 돌리려면 하위 프로젝트 이름을 붙인다. 예: `./gradlew :minirag:test`. 결과 보고서는 `<예제>/build/reports/tests/test/index.html`에 생긴다.

## 구성

하위 프로젝트 이름은 예제 디렉터리 이름과 같다. 예제 클래스들이 package 선언 없이 기본 패키지에 있으므로 테스트도 기본 패키지에 두었고, 그래서 package-private 멤버(`Gpt.KvCache`, `Main.Model` 등)를 직접 확인할 수 있다.

| 하위 프로젝트 | 테스트 | 확인하는 역할 |
|---|---|---|
| `microgpt` | `ValueTest` | 자동 미분: 연산이 그래프를 기록하고, `backward()`가 체인 룰로 기울기를 채운다. 7장의 체인 룰 예제(기울기 12)와 같은 노드가 두 경로에 쓰일 때 기울기가 더해지는 이유(`+=`)를 확인한다. |
| `microgpt` | `TokenizerTest` | 문자 단위 어휘 구성, BOS 토큰, encode와 decode의 역연산 관계 |
| `microgpt` | `GptTest` | 파라미터 수 4,192개, 로짓과 softmax의 형태, KvCache가 위치마다 자라는 것, 현재 출력이 앞 토큰에 의존하는 것, 학습 전 손실이 ln(27) 근처라는 것, 경사 하강 한 걸음이 손실을 줄이는 것 |
| `microgpt` | `SamplingTest` | temperature를 적용한 softmax(7장의 계산 예시)와 누적 확률 샘플링 |
| `serving` | `ServingModelTest` | 병렬 프리필과 순차 디코드가 같은 결과를 내는 것, KV 캐시를 재사용한 생성과 재계산한 생성이 같은 토큰 열을 내는 것, 어텐션의 가중 평균, KV 캐시 크기 공식(6장의 1 GiB, 16 GiB) |
| `safetensors` | `JsonTest`, `SafetensorsTest` | 최소 JSON 파서의 자료형 규칙과 오류 처리, safetensors 파일의 세 부분 구조(8바이트 헤더 길이, JSON 헤더, 텐서 데이터)와 읽기·쓰기 왕복 |
| `quantize` | `QuantizeTest` | 선형 양자화의 배율과 오차 상한, 블록 배율이 아웃라이어의 피해를 가두는 것, 정규 분포 분위수 격자의 모양과 균등 격자 대비 이점, 그리고 그 이점이 분포 가정에 달려 있다는 것 |
| `bpe` | `BpeTest` | 가장 흔한 쌍부터 병합하는 학습, 빈도가 같을 때의 사전순 선택, 학습 순서대로 재생하는 인코딩 |
| `minirag` | `TokenizerTest`, `ChunkTest`, `Bm25IndexTest`, `VectorIndexTest`, `RrfTest`, `SearchResultTest` | 문자 바이그램 토큰화, 문장을 자르지 않는 청킹, BM25의 IDF·빈도 포화·길이 보정, TF-IDF 벡터의 정규화와 코사인 유사도, RRF의 순위 기반 융합, 상위 K개 선별 |

## 통계적 불확실성과 테스트

예제 가운데 일부는 결과가 확률에 좌우된다. 이런 부분은 테스트에서 특정 값을 확정적으로 단정할 수 없으므로, 어떤 표본에서도 성립하는 성질이나 값의 범위만 확인한다. 각 테스트의 주석에도 같은 내용을 적어 두었다.

- **학습 결과**: microGPT의 학습 전 손실 3.34, 1,500 스텝 뒤 손실 2.27, 생성된 이름은 시드 42로 재현되는 값이지만 시드가 정한 우연이다. 테스트는 "학습 전 손실이 ln(27) ≈ 3.30 근처다"(허용 오차 0.1), "경사 하강 한 걸음이 같은 시퀀스의 손실을 줄인다"처럼 방향과 범위만 확인하고, 1,500 스텝 학습과 이름 생성은 실행하지 않는다.
- **샘플링 빈도**: 확률 0.66인 토큰이 "약 66%" 뽑힌다는 것은 대수의 법칙에 따른 근사다. `SamplingTest`는 2만 번 뽑아 빈도가 확률의 ±0.02 안에 드는지 보는데, 표준 오차(약 0.0034)의 여섯 배쯤 되는 범위라 시드를 바꿔도 실패할 확률은 무시할 만하지만 0은 아니다. 뽑기의 구간 경계 자체는 난수 값을 직접 지정해서 확정적으로 확인한다.
- **실행 시간**: 6장이 측정한 "병렬 프리필이 4.4배 빠르다", "캐시 없는 생성이 161배 느리다"는 CPU 코어 수와 JIT 상태에 따라 달라진다. `ServingModelTest`는 시간을 재지 않고 두 경로의 결과가 같다는 것과 캐시 크기 공식만 확인한다.
- **양자화 오차의 수치**: 8장의 RMS 오차 0.1541, 0.1340, 0.1058은 시드 8로 뽑은 표본 4,096개의 결과다. `QuantizeTest`는 오차의 상한(격자 간격의 절반)과 방식 사이의 크기 관계(INT8 < 4비트, 블록 배율 < 텐서 전체 배율, 분위수 격자 < 균등 격자)만 확인한다. 반대로 값이 고르게 퍼진 데이터에서는 분위수 격자가 오히려 불리하다는 것도 함께 확인해서, 이점이 "분포를 안다"는 전제에 달려 있음을 드러낸다.

반면 자동 미분, 토큰화, BPE 병합, JSON 파싱, safetensors 입출력, BM25와 코사인 유사도 계산은 입력이 같으면 결과가 정해지므로 정확한 값으로 단정한다.

## 준비물

- JDK 21 이상. Gradle wrapper가 있으므로 Gradle을 따로 설치하지 않아도 된다. 처음 실행할 때 JUnit과 AssertJ를 내려받는다.
