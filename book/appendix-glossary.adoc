[appendix]
= 용어집

본문에서 쓰는 용어를 짧은 정의와 함께 모았다. 각 항목 끝의 괄호는 그 용어를 자세히 다루는 장이다. 정의는 이 책의 문맥에 필요한 만큼만 담았으므로, 더 깊은 설명은 해당 장과 부록 "더 읽을거리"의 자료를 참고한다.

== 한글 용어

경사 하강법(gradient descent)::
손실이 줄어드는 방향(기울기의 반대 방향)으로 파라미터를 조금씩 반복해서 움직이는 최적화 방법. 모든 딥러닝 학습의 기본 절차다. (4장, 7장)

교차 엔트로피 손실(cross-entropy loss)::
학습에 쓰는 손실 함수. ``-log(정답 토큰에 배정된 확률)``로 계산하며, 정답에 낮은 확률을 줄수록 커진다. (5장)

기울기(gradient)::
파라미터가 조금 커질 때 손실이 얼마나 변하는지를 나타내는 값. 학습은 이 값의 반대 방향으로 파라미터를 움직이는 일이다. 그래디언트라고도 부른다. (4장)

다음 토큰 예측(next token prediction)::
GPT 계열 모델의 유일한 과제. 지금까지의 토큰 열을 보고 다음 토큰의 확률 분포를 내놓는다. (4장)

디코드(decode)::
추론에서 토큰을 하나씩 순차로 생성하는 단계. 앞 토큰이 정해져야 다음 토큰을 계산할 수 있어 병렬화할 수 없다. 출력 토큰 가격이 입력 토큰보다 비싼 이유다. (6장)

로짓(logit)::
모델의 마지막 계산이 어휘의 토큰마다 하나씩 내놓는 점수. 범위 제약이 없는 실수값이며, softmax를 거쳐 확률 분포가 된다. (4장)

베이스 모델(base model)::
사전학습만 마친 모델. 질문에 답하는 것이 아니라 문서를 이어 쓴다. 지시를 따르도록 추가 학습한 모델은 instruct 모델이라고 부른다. (1장)

벡터 검색(vector search)::
텍스트를 임베딩 벡터로 바꿔 저장해 두고, 질의 벡터와 거리가 가까운(코사인 유사도가 높은) 청크를 찾는 검색 방식. 학습된 임베딩 모델을 쓰면 표현이 달라도 의미가 비슷한 문서를 찾을 수 있다. (11장)

사전학습(pre-training)::
수조 토큰 규모의 코퍼스로 모델을 처음부터 학습시키는 단계. 모델의 지식 대부분이 여기서 형성된다. (1장)

샘플링(sampling)::
모델이 내놓은 확률 분포에서 다음 토큰 하나를 실제로 뽑는 일. 같은 입력에 매번 다른 출력이 나오는 이유가 이 뽑기에 있다. (5장)

선호 학습(preference learning)::
"두 답변 중 어느 쪽이 더 나은가"라는 사람의 판단 데이터로, 모델이 더 나은 쪽 답변을 내도록 가중치를 조정하는 학습 단계. RLHF와 DPO가 대표적이다. (1장)

시스템 프롬프트(system prompt)::
대화 전체에 적용되는 지시. 사용자 메시지보다 우선 취급되는 것은 학습된 경향이지 구조적 보장이 아니다. (2장)

양자화(quantization)::
파라미터 하나를 저장하는 정밀도(비트 수)를 낮춰 모델의 크기와 메모리 사용량을 줄이는 기법. 예를 들어 16비트 가중치를 4비트로 줄이면 크기가 약 4분의 1이 된다. (8장)

어텐션(attention)::
각 토큰이 시퀀스의 다른 토큰들과 얼마나 관련 있는지 계산하고, 그 관련도를 가중치로 삼아 다른 토큰들의 정보를 모아 오는 연산. 트랜스포머의 핵심 부품이다. (5장)

인컨텍스트 학습(in-context learning)::
프롬프트에 담긴 예시의 패턴을 모델이 파라미터 변경 없이 따라 하는 능력. (2장)

임베딩(embedding)::
토큰이나 텍스트를 고차원 공간의 벡터(좌표)로 나타낸 것. 의미가 비슷한 것끼리 가까운 좌표에 놓이도록 학습된다. (5장, 11장)

재순위(rerank)::
검색 상위 후보들을 cross-encoder 모델(질의와 문서를 한 쌍으로 함께 읽고 관련도를 매기는 모델)로 다시 채점해서 순서를 바로잡는 단계. (12장)

채팅 템플릿(chat template)::
role과 content로 이루어진 메시지 배열을 모델이 받는 단일 토큰 열로 직렬화하는 규칙. (10장)

청킹(chunking)::
문서를 검색과 인용의 단위가 되는 조각으로 나누는 일. 보통 문장이나 문단 경계를 지키면서 정해진 길이 이하로 자른다. (11장)

추론(inference)::
학습이 끝난 모델에 입력을 넣어 출력을 받는 일. API 호출 한 번이 추론 요청 하나다. 논리 전개를 뜻하는 추론(reasoning)과는 다른 말이다. (도입 장)

컨텍스트 부패(context rot)::
컨텍스트가 길어질수록 그 안의 정보를 활용하는 능력이 떨어지는 현상. 관련 정보의 위치와 무관하게 입력 길이 자체가 원인이 된다. (2장)

컨텍스트 윈도우(context window)::
모델이 한 번의 추론에서 다룰 수 있는 토큰의 최대 개수. 시스템 프롬프트, 대화 기록, 검색 결과, 생성할 출력이 모두 이 안에 들어가야 한다. (2장)

토크나이저(tokenizer)::
텍스트를 토큰 ID 열로 바꾸고(인코딩), 토큰 ID 열을 다시 텍스트로 되돌리는(디코딩) 구성 요소. (4장, 10장)

토큰(token)::
모델이 텍스트를 읽고 쓰는 단위이자 API의 과금 단위. 대체로 단어 하나이거나 그보다 짧은 조각이다. (도입 장, 4장)

트랜스포머(transformer)::
어텐션을 중심으로 구성된 신경망 아키텍처. 현재 LLM 대부분의 기반 구조다. (5장)

파라미터(parameter)::
모델을 이루는 학습 가능한 숫자들. 가중치(weight)와 같은 뜻으로 쓰인다. 모델이 아는 모든 것이 여기에 분산 저장된다. (1장)

파인튜닝(fine-tuning)::
이미 학습된 모델을 추가 데이터로 더 학습시키는 일의 총칭. 미세조정이라고도 한다. SFT부터 LoRA까지 비용의 자릿수가 크게 다른 작업들을 뭉뚱그린 말이므로, 어느 기법을 가리키는지 확인이 필요하다. (1장, 3장)

프리필(prefill)::
추론에서 프롬프트 전체를 병렬로 처리해 KV 캐시를 채우는 단계. 첫 토큰까지의 지연을 결정한다. (6장)

프롬프트(prompt)::
추론 요청에서 모델에 입력되는 토큰 열 전체. 사용자 질문뿐 아니라 시스템 프롬프트, 대화 기록, 검색 결과, 도구 정의까지 모두 포함한다. (2장)

프롬프트 주입(prompt injection)::
검색된 문서나 도구 결과 같은 외부 데이터에 숨은 지시문이 시스템의 지시를 덮어쓰는 공격. 모델이 토큰의 출처를 구분하지 못하기 때문에 성립한다. (2장)

프롬프트 캐싱(prompt caching)::
여러 요청이 공유하는 접두사의 계산 결과(KV 캐시)를 재사용해서 비용과 지연을 줄이는 기능. (2장, 6장)

학습(training)::
데이터를 이용해 손실이 줄어드는 방향으로 모델의 파라미터를 조정하는 과정. (도입 장, 1장)

환각(hallucination)::
모델이 사실이 아닌 내용을 그럴듯한 문장으로 생성하는 현상. 모델은 사실 여부가 아니라 다음 토큰의 확률로 문장을 만들기 때문에 생긴다. (5장)

== 영문·약어

BM25::
키워드 검색의 표준 랭킹 알고리즘. 질의 토큰이 얼마나 드문지(IDF), 문서 안에 몇 번 나오는지(TF)를 조합하고, 문서 길이를 보정해 점수를 매긴다. (11장)

BPE(Byte Pair Encoding)::
자주 함께 나타나는 인접 토큰 쌍을 병합해서 서브워드 어휘를 만드는 토크나이저 학습 알고리즘. (10장)

GGUF::
llama.cpp 생태계의 모델 파일 포맷. 양자화 방식과 실행에 필요한 메타데이터를 파일 하나에 담으며, GPU 없이 CPU나 엣지 장치에서 모델을 실행할 때 주로 쓴다. (8장)

KL 발산(KL divergence)::
두 확률 분포가 얼마나 다른지를 재는 값. 지식 증류의 손실과 RLHF의 페널티 항에 쓰인다. (7장)

KV 캐시(KV cache)::
이미 처리한 토큰의 어텐션 키(key)와 밸류(value) 벡터를 저장해 두고, 다음 토큰을 생성할 때 다시 계산하지 않도록 하는 캐시. 프롬프트 캐싱의 실체다. (5장, 6장)

LoRA(Low-Rank Adaptation)::
원본 가중치를 동결하고 작은 행렬 두 개만 학습하는 파인튜닝 기법. 소비자용 GPU에서도 실행할 수 있다. (3장)

MCP(Model Context Protocol)::
외부 시스템의 데이터와 도구를 표준화된 방식으로 모델에 연결하는 오픈 프로토콜. (2장)

RAG(Retrieval-Augmented Generation)::
질문과 관련된 문서를 검색해서 LLM의 컨텍스트에 넣어 주는 시스템. (4부)

RLHF(Reinforcement Learning from Human Feedback)::
사람의 선호 데이터로 보상 모델을 만들고, 그 점수를 최대화하도록 본 모델을 강화학습으로 조정하는 선호 학습 기법. (1장)

perplexity::
평균 교차 엔트로피에 지수 함수를 적용한 언어 모델 평가 지표. 값이 10이면 모델이 매 토큰을 10개 후보 중 하나로 균등하게 고르는 것만큼 불확실하다는 뜻이다. (7장)

safetensors::
현재 표준으로 쓰이는 가중치 저장 포맷. JSON 헤더와 텐서 데이터만 담고 실행 가능한 코드는 담지 않으므로, 파일을 읽는 과정에서 임의 코드가 실행될 위험이 없다. (8장)

SFT(Supervised Fine-Tuning)::
지시와 모범 답변의 쌍으로 모델이 지시를 따르도록 학습시키는 단계. 우리말로 감독형 미세조정이라고 한다. (1장)

softmax::
로짓들을 모두 양수로 만들고 합이 1이 되도록 정규화해 확률 분포로 바꾸는 함수. (4장, 7장)

temperature::
softmax 직전에 로짓을 나누는 수. 낮으면 확률 높은 토큰에 집중해 일관된 출력이, 높으면 다양한 출력이 나온다. (3장, 5장)

top-p / top-k::
확률 상위 일부 토큰만 샘플링 후보로 남기는 디코딩 제어. top-k는 확률 상위 k개를, top-p는 확률을 높은 순으로 더해 누적값이 p에 이를 때까지의 토큰을 남긴다. (3장)

TTFT / TPOT::
추론 지연의 두 지표. TTFT(time to first token)는 첫 토큰까지의 시간으로 프리필이 결정하고, TPOT(time per output token)은 토큰당 생성 시간으로 디코드가 결정한다. (6장)

Vector DB::
고차원 벡터의 근사 최근접 이웃(ANN) 검색에 특화된 저장소. 벡터 인덱싱, 유사도 계산, 메타데이터 필터링을 책임진다. (11장)
