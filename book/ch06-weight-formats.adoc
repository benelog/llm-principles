= 가중치 저장 포맷

== 모델 파일의 정체

2부에서 학습시킨 microGPT의 실체는 4,192개의 실수값이었다. 프로덕션 모델도 마찬가지로, 학습이 끝난 모델의 실체는 텐서(다차원 배열)들의 모음이다. 토큰 임베딩 행렬, 각 블록의 어텐션 가중치, MLP 가중치가 이름이 붙은 텐서로 존재한다. 모델 파일이란 이 텐서들을 이름과 함께 담은 바이너리다.

Hugging Face에서 모델을 받으면 `model.safetensors` 같은 파일이 수 GB를 차지한다. 이 파일을 어떤 형식으로 저장하느냐가 오픈 모델 호환성의 첫 번째 표준이다. 현재 쓰이는 포맷은 세 계열이다.

[cols="1,3"]
|===
| 포맷 | 특징

| Safetensors
| 현재의 표준. 헤더가 JSON이라 어느 언어에서든 해석할 수 있고, 메모리 매핑을 지원하며, 코드 실행 없이 데이터만 읽으므로 안전하다.

| GGUF
| llama.cpp 생태계의 표준. 양자화 정보를 포함하고 CPU와 엣지 환경에 강하다. Ollama가 이 포맷을 쓴다.

| PyTorch (.bin/.pt)
| 레거시 포맷. 파이썬 pickle 기반이라 파일을 여는 것만으로 임의 코드가 실행될 수 있는 보안 취약점이 있다.
|===

== pickle의 문제와 Safetensors의 등장

레거시 포맷의 문제를 짚고 넘어갈 필요가 있다. PyTorch의 기본 저장 방식은 파이썬 pickle 직렬화 위에 만들어져 있다. pickle은 파이썬 객체를 저장하면서 "이 객체를 복원하는 방법"까지 담는데, 그 복원 방법에 임의의 함수 호출이 들어갈 수 있다. 악의적으로 만든 모델 파일을 `torch.load`로 여는 순간 학습된 숫자 대신 공격 코드가 실행될 수 있다는 뜻이다.

모델을 "누구나 올리고 누구나 받는" 허브가 성장하면서 이 위험은 실제 공격 경로가 되었다. Safetensors는 이 문제를 구조적으로 제거한 포맷이다. 파일에는 순수한 데이터와 JSON 메타데이터만 있고, 실행 가능한 것이 아무것도 없다. 여기에 두 가지 실용적 장점이 더해졌다. 헤더만 읽으면 전체 데이터를 메모리에 올리지 않고도 모델 구조를 알 수 있고, 메모리 매핑으로 필요한 부분만 지연 로딩할 수 있다.

GGUF는 다른 방향의 요구에서 나왔다. GPU 없이 CPU에서 모델을 돌리려면 가중치를 4비트, 5비트로 압축하는 양자화가 필수인데, GGUF는 양자화 방식과 실행에 필요한 메타데이터를 파일 하나에 담아 llama.cpp 계열 엔진이 바로 실행할 수 있게 한다.

== safetensors를 직접 만들어 보기

포맷이 얼마나 단순한지는 직접 만들어 보면 안다. safetensors 파일의 구조는 세 부분이다. 처음 8바이트에 헤더 길이, 이어서 JSON 헤더, 그 뒤에 텐서 데이터가 이어진다. 이 절의 코드는 `examples/go/safetensors`에 있으며 표준 라이브러리만으로 동작한다.

헤더에 기록되는 텐서 하나의 메타데이터를 Go 타입으로 표현하면 다음과 같다.

[source,go]
----
include::../examples/go/safetensors/main.go[tag=header-type,indent=0]
----

파일을 쓰는 쪽은 텐서들을 바이트로 이어 붙이면서 각 텐서의 위치를 헤더에 기록한다.

[source,go]
----
include::../examples/go/safetensors/main.go[tag=write,indent=0]
----

읽는 쪽은 그 반대다. 헤더 길이를 읽고, JSON을 해석하고, 오프셋으로 텐서를 찾아간다.

[source,go]
----
include::../examples/go/safetensors/main.go[tag=read,indent=0]
----

실행하면 어휘 4개, 임베딩 차원 3인 장난감 모델이 저장되고 복원된다. 실제 LLM의 safetensors 파일도 텐서가 수백 개이고 원소가 수십억 개일 뿐 구조는 같다. 파서 어디에도 코드 실행이 없다는 것, JSON과 바이트 오프셋만 다루면 어떤 언어로도 읽고 쓸 수 있다는 것이 이 포맷이 표준이 된 이유를 그대로 보여 준다.

== 가중치 안에 무엇이 들어 있나

이 텐서들 안에 무엇이 들어 있는지 다시 확인해 두자. 다국어를 지원하는 모델도 언어별 파일이 따로 있지 않다. 한국어 문법도, 영어 어휘도, 코드 작성 능력도 전부 같은 텐서들의 숫자값에 "분산 표현"으로 녹아 있다. 1부에서 모델 레이어의 정보를 선택적으로 빼내기 어렵다고 한 이유가 이 저장 방식에 있다. 특정 지식을 담당하는 파일이나 영역이 없으므로, 파일을 들여다봐서 모델이 무엇을 아는지 알아낼 방법도 없다.

가중치 파일은 숫자를 담을 뿐, 그 숫자를 어떤 구조에 배치해서 실행할지는 알려 주지 않는다. 그 정보는 별도의 설정 파일에 있으며, 그것이 두 번째 표준이다. 다음 장에서 다룬다.
