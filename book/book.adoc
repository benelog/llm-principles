[preface]
== 들어가며

이 책은 LLM(대규모 언어 모델)을 쓰는 시스템을 만드는 애플리케이션 개발자가 알아야 할 원리를 네 개의 부로 정리한다.

* *1부*는 LLM에 정보를 전달하는 방법의 전체 지도를 그린다. 파인튜닝, RAG, 프롬프트 엔지니어링처럼 이름과 유행이 제각각인 기법들을 모델 레이어와 프롬프트 레이어라는 두 분류로 정돈하고, 어느 쪽에도 깔끔하게 속하지 않는 회색지대까지 다룬다.
* *2부*는 그 지도의 밑바탕인 LLM의 동작 원리를 코드로 확인한다. Andrej Karpathy의 microGPT를 해설하면서 토크나이저, 자동 미분, 어텐션, 학습과 추론을 직접 실행되는 작은 구현으로 살펴본다.
* *3부*는 학습된 모델이 유통되는 방식을 다룬다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 배경에 어떤 표준이 있는지 확인한다.
* *4부*는 실무에서 가장 자주 만드는 응용인 RAG를 구성요소 단위로 분해하고, 성능이 안 나올 때의 진단 순서를 제시한다.

이론만 읽고 끝나지 않도록 실행 가능한 예제를 함께 제공한다. 예제는 이 책의 저장소 `examples/` 디렉토리에 있으며, 두 가지 환경으로 준비했다.

* *Go*: 외부 의존성 없이 표준 라이브러리만으로 핵심 원리를 구현했다. `go run .` 한 번으로 실행된다.
** `examples/go/microgpt`: microGPT의 Go 포팅 (2부)
** `examples/go/safetensors`: safetensors 파일을 만들고 읽는 파서 (3부)
** `examples/go/minirag`: 청킹, BM25, 벡터 검색, 하이브리드 융합을 담은 검색 파이프라인 (4부)
* *Spring AI*: 자바 생태계에서 같은 개념을 어떻게 다루는지 보여 준다. API 키 없이 로컬 임베딩 모델로 실행된다.
** `examples/spring-ai`: RAG 파이프라인과 디코딩 파라미터 제어 (1부, 4부)

본문의 코드는 모두 이 예제 프로젝트의 소스를 그대로 인용한 것이다. 책의 코드와 저장소의 코드는 항상 같다.

[[part-layers]]
= 1부: LLM에 정보를 전달하는 레이어

[partintro]
--
LLM에 정보를 넣는 기법은 많다. 파인튜닝, RAG, 프롬프트 엔지니어링, LoRA, 메모리 시스템. 이름도 많고 유행도 빠르지만, 이 기법들은 결국 두 갈래로 나뉜다. 모델의 파라미터를 바꾸는 방법과, 추론 시점에 입력 토큰으로 넣는 방법이다. 1부는 이 두 레이어를 한 장씩 살펴보고, 어느 쪽에도 깔끔하게 분류되지 않는 회색지대를 정리한다. 어떤 기법이 어느 레이어에 속하는지 알면 그 기법의 비용, 지속성, 적용 시점을 바로 추론할 수 있다.

[[part-microgpt]]
= 2부: 동작 원리 들여다보기, microGPT

[partintro]
--
1부의 분류는 LLM이 "학습된 파라미터로 다음 토큰을 예측하는 기계"라는 사실 위에 서 있다. 2부는 그 사실을 코드로 확인한다. Andrej Karpathy의 microGPT는 의존성 없는 순수 파이썬 200줄로 GPT를 학습하고 추론하는 프로젝트다. 이 책에서는 원본과 같은 구조의 Go 포팅(`examples/go/microgpt`)을 따라가며, 토큰화에서 샘플링까지 전 과정을 실행되는 코드로 살펴본다.

[[part-standards]]
= 3부: 오픈 모델을 움직이는 표준

[partintro]
--
2부에서 우리가 직접 학습시킨 모델은 메모리 안의 숫자 배열이었다. 그 숫자들이 파일로 저장되어 유통되는 순간부터는 호환성 문제가 생긴다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 것은 당연한 일이 아니다. 3부는 그 배경에 있는 세 가지 사실상 표준(de facto standard)인 가중치 저장 포맷, 모델 아키텍처 규약, 소수 아키텍처로의 수렴을 확인한다.
--
