[preface]
== 들어가며

LLM(대규모 언어 모델)으로 무언가를 만드는 개발자 대부분은 모델을 만들지 않는다. API를 호출하고, 프롬프트를 조립하고, 검색한 문서를 컨텍스트에 넣고, 응답을 서비스에 연결한다. 모델 학습은 전문 조직의 일이 되었지만, 그 모델 위에 시스템을 만드는 일은 애플리케이션 개발자의 일상이 되었다.

그런데 원리를 모르고 이 일을 하면 문제가 생겼을 때 원인을 찾지 못해 막힌다. temperature는 무엇을 조절하는지, 프롬프트 캐싱은 왜 앞부분이 같아야 적중하는지, 출력 토큰은 왜 입력 토큰보다 비싼지, RAG의 답변이 이상할 때 모델과 검색 중 어디부터 의심해야 하는지. 실무에서 매일 만나는 이런 질문의 답은 모델의 동작 원리와 주변 규약에서 나온다. 이 책은 그 원리와 규약을 머신러닝 배경이 없는 애플리케이션 개발자도 읽을 수 있게, 실행되는 코드와 함께 정리한다.

이 질문들이 낯설어도 괜찮다. 독자가 미리 알아야 할 것이 아니라 이 책이 답할 질문들이다.

=== 예상 독자와 사전 지식

이 책은 서버나 애플리케이션을 개발해 본 사람을 독자로 전제한다. JSON을 주고받는 API를 다뤄 봤고, 예제로 쓰는 자바 코드를 읽을 수 있으면 충분하다.

머신러닝 배경은 전제하지 않는다. LLM API를 호출해 본 적이 없어도 따라올 수 있도록, 본문 앞의 도입 장에서 API 호출 한 번을 해부하며 토큰부터 정리한다. 같은 장에서 토큰이 모델 안에서 숫자 배열(벡터)로 바뀐다는 것과 학습이 파라미터를 조정하는 과정도 작은 숫자 예로 먼저 보여 준다. 본문은 수식 대신 실행되는 코드로 원리를 보여 주고, 그 코드 뒤의 벡터, 미분, 확률 같은 개념은 1부의 마지막 장인 4장에 모았다. 이 개념들이 낯설면 4장을 먼저 읽거나 개념이 나올 때 찾아 읽으면 된다. 4장은 식마다 숫자를 넣은 계산을 붙였고, 식에 쓰는 표기와 읽는 법을 첫머리의 표로 정리했다. 4장에는 1부를 읽는 데 필요한 수학만 두었다. 정규 분포, 회귀, 유의성 검정처럼 다른 장이 참조하는 통계 개념은 부록 통계 참고에 있으니 본문이 가리킬 때 찾아 읽으면 된다. 앞장에서 정의한 용어를 잊었을 때는 부록 용어집에서 찾으면 된다.

=== 책의 구성

이 책은 도입 장 하나와 네 개의 부, 부록 세 개로 이루어져 있다.

* **도입 장**은 LLM API 호출 한 번을 요청과 응답의 필드 단위로 해부한다. 학습, 추론, 토큰, 컨텍스트 윈도우 같은 기본 개념을 여기서 정의하고, 1부의 전제인 토큰의 벡터 표현과 학습이 하는 일을 숫자 예로 소개한다. LLM을 처음 다루는 독자는 이 장부터 읽으면 된다.

* **1부**는 LLM의 동작 원리를 코드로 확인한다. Andrej Karpathy의 microGPT를 해설하며 토크나이저, 자동 미분, 어텐션, 학습과 추론을 실행되는 작은 구현으로 살펴본다. 이어서 프리필과 디코드, KV 캐시가 만드는 프로덕션 추론의 비용 구조를 측정하고, 마지막 장에서 그 코드 뒤의 수학 개념을 학습 루프 순서대로 정리한다.
* **2부**는 LLM에 정보를 전달하는 방법의 전체 지도를 그린다. 파인튜닝, RAG, 프롬프트 엔지니어링처럼 이름과 유행이 제각각인 기법들을 모델 레이어와 프롬프트 레이어라는 두 분류로 나누고, 어느 쪽에도 깔끔하게 속하지 않는 회색지대까지 다룬다. 분류의 기준은 1부에서 본 파라미터와 입력 토큰이다.
* **3부**는 학습된 모델이 유통되는 방식을 다룬다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 배경의 표준을 확인하고, 응용 개발과 가장 가까운 규약인 토크나이저와 채팅 템플릿까지 살펴본다.
* **4부**는 실무에서 가장 자주 만드는 응용인 RAG를 구성요소 단위로 분해하고, 성능이 안 나올 때의 진단 순서를 제시한다. 마지막으로 긴 컨텍스트와 에이전틱 검색이 RAG의 경계를 어떻게 옮기는지 확인한다.
* **부록**은 통계 참고, 더 읽을거리, 용어집이다. 통계 참고에는 정규 분포, 주성분 분석, 회귀, 마르코프 체인, 유의성 검정처럼 본문이 참조하는 통계 개념을 숫자 계산과 함께 정리했다.

=== 예제를 파이썬으로 쓰지 않은 이유

머신러닝 생태계의 표준 언어는 파이썬이고, LLM을 다루는 책의 예제도 대부분 파이썬이다. 이 책은 예제를 전부 자바로 작성했다. 이 책의 독자인 애플리케이션 서버 개발자가 실무에서 많이 쓰는 언어이기 때문이다. LLM을 호출하는 코드는 지금 운영 중인 서버 안으로 들어간다. 원리를 익히는 언어와 적용할 언어가 같으면 파이썬 예제를 자바로 옮겨 적는 단계가 없어진다.

예제는 두 종류로 나뉜다.

원리 구현 예제는 JDK 표준 라이브러리만으로 GPT 학습, safetensors 파싱, BPE 토큰화, 검색 파이프라인을 구현했다. 빌드 도구나 프레임워크 설치 없이 `java Main.java` 한 번으로 실행된다. 어텐션과 역전파 같은 알고리즘을 라이브러리 호출 한 줄로 대신하지 않고 배열과 반복문으로 직접 구현해서, 계산 과정을 코드에서 그대로 읽을 수 있다.

실무 구성 예제는 Spring AI를 쓴다. 자바와 Spring은 엔터프라이즈 서버 개발에서 가장 널리 쓰이는 조합이고, 성숙한 운영 도구와 방대한 기존 코드베이스가 있다. Spring AI는 모델 제공자와 벡터 저장소를 인터페이스로 추상화하므로, 예제에서 익힌 구성을 제공자만 바꿔 운영 환경으로 가져갈 수 있다. Spring AI 예제는 원리를 기존 서비스에 통합할 때 실제로 작성하는 코드와 설정을 보여 준다.

이 선택에는 부수 효과도 하나 있다. 1부의 GPT 구현, 3부의 safetensors 파서, 4부의 검색 파이프라인 모두 파이썬 없이 동작한다. LLM의 원리와 오픈 모델의 표준은 특정 언어 전용이 아니다. 3부에서 확인할 표준의 성질("JSON과 바이트 오프셋만 다루면 어떤 언어로도 읽고 쓸 수 있다")을 이 책의 예제가 직접 보여 준다.

=== 예제 코드 안내

예제는 이 책의 저장소 `examples/` 디렉터리에 있으며, 두 가지 환경으로 준비했다.

* *순수 자바*: JDK 표준 라이브러리만으로 핵심 원리를 구현했다. JDK 22 이상에서 `java Main.java` 한 번으로 실행된다.
** `examples/java/microgpt`: microGPT의 자바 포팅 (1부)
** `examples/java/serving`: 프리필·디코드와 KV 캐시의 비용 구조 측정 (1부)
** `examples/java/safetensors`: safetensors 파일을 만들고 읽는 파서 (3부)
** `examples/java/quantize`: 선형 양자화, 블록 배율, 정규 분포 격자의 오차 측정 (3부)
** `examples/java/bpe`: BPE 토크나이저의 병합 학습과 인코딩 (3부)
** `examples/java/minirag`: 청킹, BM25, 벡터 검색, 하이브리드 융합을 담은 검색 파이프라인 (4부)
** `examples/java-tests`: 위 예제들의 주요 클래스가 하는 일을 확인하는 JUnit 테스트. Gradle로 실행한다
** `examples/math-lab`: 4장과 부록 통계 참고의 수치를 Apache Commons Math로 검산하는 실습. Gradle로 실행한다
* *Spring AI*: 자바 생태계에서 같은 개념을 어떻게 다루는지 보여 준다. API 키 없이 로컬 임베딩 모델로 실행된다.
** `examples/spring-ai`: RAG 파이프라인과 디코딩 파라미터 제어 (2부, 4부)

본문의 코드는 모두 예제 프로젝트의 소스를 그대로 인용했으므로 책과 저장소의 코드는 항상 같다.

[[part-microgpt]]
= 1부: 동작 원리 들여다보기, microGPT

[partintro]
--
LLM은 학습된 파라미터로 다음 토큰을 예측하는 기계다. 1부는 이 사실을 코드로 확인한다. Andrej Karpathy의 microGPT는 의존성 없는 순수 파이썬 200줄로 GPT를 학습하고 추론하는 프로젝트다. 이 책에서는 원본과 같은 구조의 자바 포팅(`examples/java/microgpt`)을 따라가며 토큰화에서 샘플링까지 전 과정을 실행되는 코드로 살펴본다. 이어서 같은 구조를 프로덕션 규모로 확장했을 때의 추론 비용 구조를 측정하고, 마지막 장에서 이 코드 뒤의 수학 개념을 한곳에 정리한다. 2부부터 다룰 파인튜닝, 프롬프트 캐싱, 양자화, 벡터 검색은 모두 여기서 볼 파라미터, 어텐션, KV 캐시, 확률 분포를 다루는 기법이다.

[[part-layers]]
= 2부: LLM에 정보를 전달하는 레이어

[partintro]
--
LLM에 정보를 넣는 기법은 파인튜닝, RAG, 프롬프트 엔지니어링, LoRA, 메모리 시스템처럼 이름도 많고 유행도 빠르지만, 두 가지로 나뉜다. 모델의 파라미터를 바꾸는 방법과 추론 시점에 입력 토큰으로 넣는 방법이다. 1부의 microGPT로 말하면 앞의 것은 학습 루프가 하는 일이고, 뒤의 것은 forward 계산에 넣는 토큰 열을 바꾸는 일이다. 2부는 이 두 레이어를 한 장씩 살펴보고, 어느 쪽에도 깔끔하게 분류되지 않는 회색지대를 정리한다. 기법이 어느 레이어에 속하는지 알면 그 기법의 비용, 지속성, 적용 시점을 바로 추론할 수 있다.

[[part-standards]]
= 3부: 오픈 모델을 움직이는 표준

[partintro]
--
1부에서 직접 학습시킨 모델은 메모리 안의 숫자 배열이었다. 이 숫자들을 파일로 저장해 유통하는 순간부터 호환성 문제가 생긴다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 것은 당연한 일이 아니다. 3부는 그 배경에 있는 세 가지 사실상 표준(de facto standard)인 가중치 저장 포맷, 모델 아키텍처 규약, 소수 아키텍처로의 수렴을 확인한다. 그 규약 가운데 응용 개발자의 비용과 장애 진단에 바로 영향을 주는 토크나이저와 채팅 템플릿은 따로 한 장으로 살펴본다.

[[part-rag]]
= 4부: RAG 시스템

[partintro]
--
4부는 2부에서 컨텍스트 공급 레이어로 분류한 RAG를 실무 시스템으로 다룬다. 먼저 검색 파이프라인을 자바 표준 라이브러리만으로 바닥부터 구현해 각 단계의 원리를 확인하고, Spring AI로 실제 임베딩 모델을 쓰는 구성으로 확장한다. 이어서 한국어 검색 품질을 크게 바꾸는 구성요소를 살펴보고, 성능이 안 나올 때 어디부터 손볼지 진단 순서를 정리한다. 마지막 장에서는 긴 컨텍스트와 에이전틱 검색이 이 구성을 어떻게 바꾸는지 확인한다.
