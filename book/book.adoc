[preface]
== 들어가며

LLM(대규모 언어 모델)으로 무언가를 만드는 개발자 대부분은 모델을 만들지 않는다. API를 호출하고, 프롬프트를 조립하고, 검색된 문서를 컨텍스트에 넣고, 응답을 받아 서비스에 연결한다. 모델을 학습시키는 일은 전문 조직의 일이 되었지만, 그 모델 위에 시스템을 만드는 일은 애플리케이션 개발자의 일상이 되었다.

그런데 이 일은 원리를 모르면 오래가지 못한다. temperature는 무엇을 조절하는 것인지, 프롬프트 캐싱은 왜 앞부분이 같아야 적중하는지, 출력 토큰은 왜 입력 토큰보다 비싼지, RAG의 답변이 이상할 때 모델과 검색 중 어디부터 의심해야 하는지. 실무에서 매일 만나는 이런 질문의 답은 전부 모델의 동작 원리와 그 주변의 규약에서 기계적으로 유도된다. 이 책은 그 원리와 규약을 애플리케이션 개발자의 눈높이에서, 실행되는 코드와 함께 정리한다.

=== 책의 구성

이 책은 네 개의 부로 이루어져 있다.

* *1부*는 LLM에 정보를 전달하는 방법의 전체 지도를 그린다. 파인튜닝, RAG, 프롬프트 엔지니어링처럼 이름과 유행이 제각각인 기법들을 모델 레이어와 프롬프트 레이어라는 두 분류로 정돈하고, 어느 쪽에도 깔끔하게 속하지 않는 회색지대까지 다룬다.
* *2부*는 그 지도의 밑바탕인 LLM의 동작 원리를 코드로 확인한다. Andrej Karpathy의 microGPT를 해설하면서 토크나이저, 자동 미분, 어텐션, 학습과 추론을 직접 실행되는 작은 구현으로 살펴본다. 이어서 프리필과 디코드, KV 캐시가 만드는 프로덕션 추론의 비용 구조를 측정으로 확인한다.
* *3부*는 학습된 모델이 유통되는 방식을 다룬다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 배경에 어떤 표준이 있는지 확인하고, 응용 개발과 가장 가까운 규약인 토크나이저와 채팅 템플릿까지 내려간다.
* *4부*는 실무에서 가장 자주 만드는 응용인 RAG를 구성요소 단위로 분해하고, 성능이 안 나올 때의 진단 순서를 제시한다. 마지막으로 긴 컨텍스트와 에이전틱 검색이 RAG의 경계를 어떻게 옮기는지 확인한다.

=== 예제를 파이썬으로 쓰지 않은 이유

머신러닝 생태계의 표준 언어는 파이썬이고, LLM을 다루는 책의 예제도 대부분 파이썬으로 쓰인다. 이 책은 다른 선택을 했다. 예제를 Go와 자바(Spring)로 작성했다. 이 책의 독자인 애플리케이션 서버 개발자가 실무에서 많이 쓰는 기술이기 때문이다. LLM을 호출하는 코드는 결국 지금 운영 중인 서버 안으로 들어간다. 원리를 익히는 언어와 그 원리를 적용할 언어가 같으면, 배운 것을 실무 코드로 옮기는 번역 단계가 사라진다.

두 언어는 역할을 나눠 맡는다.

Go는 원리 구현을 맡았다. 외부 의존성 없이 표준 라이브러리만으로 GPT 학습, safetensors 파싱, BPE 토큰화, 검색 파이프라인을 구현했으므로, 프레임워크 설치 없이 `go run .` 한 번으로 모든 예제가 실행된다. 문법에 숨겨진 동작이 적은 명시적인 언어라서 어텐션과 역전파 같은 알고리즘이 라이브러리 호출 뒤에 숨지 않고 코드에 그대로 드러난다. 또한 컴파일된 단일 바이너리로 배포되고 같은 작업에서 파이썬 런타임보다 메모리를 적게 사용하므로, 원리 학습용 코드를 넘어 실제 서버나 CLI 도구로 키워 가기에도 알맞다.

자바는 실무 구성을 맡았다. 자바와 Spring은 엔터프라이즈 서버 개발에서 가장 널리 쓰이는 조합이고, 성숙한 운영 도구와 방대한 기존 코드베이스라는 자산을 갖고 있다. Spring AI는 모델 제공자와 벡터 저장소를 인터페이스로 추상화하므로, 예제에서 익힌 구성을 제공자만 바꿔 운영 환경으로 가져갈 수 있다. Go 예제가 원리를 보여 준다면, Spring AI 예제는 그 원리가 기존 서비스에 통합되는 실제 작업의 형태를 보여 준다.

이 선택에는 부수적인 증명 효과도 있다. 2부의 GPT 구현도, 3부의 safetensors 파서도, 4부의 검색 파이프라인도 파이썬 없이 동작한다. LLM의 원리와 오픈 모델의 표준은 특정 언어의 소유물이 아니며, 3부에서 확인할 "JSON과 바이트 오프셋만 다루면 어떤 언어로도 읽고 쓸 수 있다"는 표준의 성질이 이 책의 예제 구성 자체로 증명된다.

=== 예제 코드 안내

예제는 이 책의 저장소 `examples/` 디렉토리에 있으며, 두 가지 환경으로 준비했다.

* *Go*: 외부 의존성 없이 표준 라이브러리만으로 핵심 원리를 구현했다. `go run .` 한 번으로 실행된다.
** `examples/go/microgpt`: microGPT의 Go 포팅 (2부)
** `examples/go/serving`: 프리필·디코드와 KV 캐시의 비용 구조 측정 (2부)
** `examples/go/safetensors`: safetensors 파일을 만들고 읽는 파서 (3부)
** `examples/go/bpe`: BPE 토크나이저의 병합 학습과 인코딩 (3부)
** `examples/go/minirag`: 청킹, BM25, 벡터 검색, 하이브리드 융합을 담은 검색 파이프라인 (4부)
* *Spring AI*: 자바 생태계에서 같은 개념을 어떻게 다루는지 보여 준다. API 키 없이 로컬 임베딩 모델로 실행된다.
** `examples/spring-ai`: RAG 파이프라인과 디코딩 파라미터 제어 (1부, 4부)

본문의 코드는 모두 이 예제 프로젝트의 소스를 그대로 인용한 것이다. 책의 코드와 저장소의 코드는 항상 같다.

[[part-microgpt]]
= 2부: 동작 원리 들여다보기, microGPT

[partintro]
--
1부의 분류는 LLM이 "학습된 파라미터로 다음 토큰을 예측하는 기계"라는 사실 위에 서 있다. 2부는 그 사실을 코드로 확인한다. Andrej Karpathy의 microGPT는 의존성 없는 순수 파이썬 200줄로 GPT를 학습하고 추론하는 프로젝트다. 이 책에서는 원본과 같은 구조의 Go 포팅(`examples/go/microgpt`)을 따라가며, 토큰화에서 샘플링까지 전 과정을 실행되는 코드로 살펴본다. 마지막 장에서는 같은 구조를 프로덕션 규모로 확장했을 때의 추론 비용 구조를 측정으로 확인한다.

[[part-standards]]
= 3부: 오픈 모델을 움직이는 표준

[partintro]
--
2부에서 우리가 직접 학습시킨 모델은 메모리 안의 숫자 배열이었다. 그 숫자들이 파일로 저장되어 유통되는 순간부터는 호환성 문제가 생긴다. Hugging Face에서 받은 모델이 누가 만들었든 바로 실행되는 것은 당연한 일이 아니다. 3부는 그 배경에 있는 세 가지 사실상 표준(de facto standard)인 가중치 저장 포맷, 모델 아키텍처 규약, 소수 아키텍처로의 수렴을 확인한다. 그리고 그 규약들 가운데 응용 개발자의 비용과 장애 진단에 바로 닿는 토크나이저와 채팅 템플릿을 따로 한 장으로 살펴본다.
