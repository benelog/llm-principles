= 모델 레이어: 가중치에 새기는 정보

== 파라미터라는 저장소

LLM의 실체는 숫자다. 수십억에서 수조 개의 실수값이 신경망의 가중치(파라미터)로 배열되어 있고, 모델이 아는 모든 것은 이 숫자들 속에 들어 있다. 한국어 문법도, 파이썬 문법도, 세계 지리도 별도의 데이터베이스가 아니라 같은 숫자 더미에 함께 저장되어 있다.

모델 레이어는 이 숫자들을 직접 수정해서 정보를 전달하는 방식이다. 학습이라는 절차를 거쳐 정보를 파라미터에 새기면, 그 정보는 이후의 모든 요청에 지속적으로 적용된다. 대신 학습에는 GPU 시간과 데이터 준비 비용이 들고, 한번 새긴 정보를 선택적으로 빼내기는 어렵다.

이 장에서는 모델 레이어에 속하는 기법들을 학습 파이프라인의 순서대로, 그리고 특수한 변형들까지 하나씩 살펴본다.

== 사전학습: 세계관의 형성

사전학습(pre-training)은 대량의 텍스트 코퍼스로 모델을 처음부터 학습시키는 단계다. 웹 문서, 책, 논문, 코드 저장소에서 모은 수조 토큰의 텍스트에서 "다음 토큰 맞히기"를 반복하면, 모델은 언어의 문법부터 세상 지식까지를 통계적 패턴으로 흡수한다.

여기서 기억할 것은 코퍼스의 분포가 곧 모델의 세계관이 된다는 점이다. 학습 데이터에 많이 등장한 주제는 잘 알고, 드물게 등장한 주제는 부정확하게 알고, 등장하지 않은 주제(예: 학습 마감일 이후의 사건)는 모른다. 데이터에 담긴 편향도 그대로 흡수된다. "이 모델은 왜 이 주제에 약한가"라는 질문의 답은 대부분 사전학습 코퍼스의 구성에 있다.

그래서 사전학습의 실제 작업 대부분은 학습 자체가 아니라 데이터 준비다. 웹 크롤링 원본에서 중복을 제거하고, 스팸과 기계 생성 텍스트를 걸러 내고, 코드와 수학처럼 추론 능력에 기여하는 데이터의 비중을 조절하는 정제 파이프라인이 모델 품질을 크게 좌우한다. 같은 아키텍처라도 데이터 구성이 다르면 다른 모델이 나온다.

사전학습만 마친 모델을 베이스 모델(base model)이라고 부른다. 베이스 모델은 질문에 답하는 것이 아니라 문서를 이어 쓴다. "한국의 수도는"이라고 입력하면 "서울이다"라고 답할 수도 있지만, "어디인가? 이 문제는 초등학교 시험에 자주 나온다"처럼 문서의 연속으로 이어 갈 수도 있다. 대화형 도우미로 만들려면 뒤에서 다룰 추가 학습이 필요하다.

== 연속 사전학습: 도메인 전문가 만들기

연속 사전학습(continued pre-training)은 이미 학습된 모델을 특정 도메인의 코퍼스로 추가 학습시키는 방식이다. 의료 논문, 법률 문서, 사내 코드베이스처럼 일반 코퍼스에 충분히 담기지 않은 텍스트를 대량으로 넣어 도메인 지식을 보강한다.

일반 사전학습과 절차는 같고 데이터만 다르다. 처음부터 학습하는 것보다 비용이 훨씬 적게 들면서 도메인 용어와 문체를 흡수시킬 수 있다. 다만 도메인 데이터에 치우쳐 학습하면 원래 갖고 있던 일반 능력이 퇴화하는 부작용(catastrophic forgetting)이 생길 수 있어서, 일반 코퍼스를 일정 비율 섞는 것이 보통이다.

== 감독형 미세조정: 형식과 태스크 학습

감독형 미세조정(SFT, Supervised Fine-Tuning)은 "이런 입력에는 이런 출력"이라는 입출력 페어를 학습시키는 단계다. 질문과 모범 답변, 지시와 수행 결과 같은 페어 수만 건이면 베이스 모델이 지시를 따르는 모델(instruct model)로 바뀐다.

SFT가 주입하는 것은 지식보다는 형식, 스타일, 태스크 수행 방식이다. "질문을 받으면 문서를 이어 쓰지 말고 답변을 시작한다", "코드를 요청받으면 코드 블록으로 감싼다" 같은 행동 양식이 여기서 결정된다. 새로운 사실 지식을 SFT로 넣는 것은 효율이 낮다. 지식은 사전학습 단계에서 대량의 텍스트로 흡수되는 것이고, SFT 데이터는 그 지식을 꺼내 쓰는 방법을 가르친다.

== 선호 학습: 가치와 취향 새기기

선호 학습은 "두 답변 중 어느 쪽이 더 나은가"라는 사람의 판단을 가중치에 새기는 단계다. 정답이 하나로 정해지지 않는 품질(유용함, 무해함, 말투)을 다루기 위한 방법이다.

RLHF(Reinforcement Learning from Human Feedback):: 원조 격의 방법. 사람이 매긴 선호 데이터로 보상 모델(reward model)을 먼저 학습시키고, 그 보상 모델의 점수를 최대화하도록 본 모델을 강화학습(주로 PPO)으로 조정한다. ChatGPT를 만든 핵심 기법으로 알려져 있다.

DPO(Direct Preference Optimization):: 보상 모델과 강화학습 없이, 선호 페어("이 답변이 저 답변보다 낫다")로 직접 최적화한다. 파이프라인이 단순해서 널리 쓰인다.

KTO, IPO 등:: DPO의 변형들이다. KTO는 페어가 아닌 개별 답변의 좋음/나쁨 판정만으로 학습하고, IPO는 DPO의 과적합 문제를 보정한다.

선호 학습의 결과는 모델의 "성격"으로 나타난다. 같은 베이스 모델이라도 선호 데이터가 다르면 답변의 장황함, 신중함, 거절 성향이 달라진다.

== 검증 가능 보상 강화학습: 채점기가 선생님

RLVR(Reinforcement Learning with Verifiable Rewards)은 사람의 선호 대신 자동으로 채점할 수 있는 신호로 학습한다. 수학 문제의 정답 일치 여부, 코드의 테스트 통과 여부, 컴파일 성공 여부처럼 프로그램이 판정할 수 있는 결과가 보상이 된다.

사람의 평가가 필요 없으므로 학습 신호를 대량으로 만들 수 있고, "그럴듯해 보이는 답"이 아니라 "실제로 맞는 답"에 보상이 간다. 긴 사고 과정을 거쳐 답을 찾는 추론 특화 모델들이 이 방식으로 학습된다.

== 모델 편집: 사실 하나만 수정하기

모델 편집(model editing)은 재학습 없이 특정 사실 하나를 가중치에서 직접 수정하는 기법이다. "프랑스의 수도는 파리"라는 연관이 가중치의 어느 부분에 저장되어 있는지 찾아내서 그 부분만 바꾸는 식이다. ROME, MEMIT, MEND 같은 연구가 있다.

이 접근이 흥미로운 이유는 분산 표현의 한계를 정면으로 건드리기 때문이다. 지식이 파라미터 전체에 퍼져 있다면 사실 하나를 수정하는 것은 불가능해야 하는데, 실제로는 특정 레이어의 특정 부분이 특정 연관에 크게 기여한다는 것이 밝혀져 있다. 다만 수정의 부작용(관련 지식까지 바뀌는 문제)이 완전히 통제되지 않아서 아직 연구 단계에 가깝다.

== 지식 증류: 큰 모델을 작은 모델로

지식 증류(distillation)는 큰 모델(teacher)의 능력을 작은 모델(student)로 압축하는 기법이다. 큰 모델이 만든 출력이나 출력 확률 분포를 작은 모델이 따라 배우게 한다. 정답 레이블만 배우는 것보다 "큰 모델이 각 선택지에 어느 정도의 확률을 주었는가"라는 부드러운 신호까지 배우는 쪽이 효과적이다.

실무에서는 대형 모델로 고품질 학습 데이터를 생성하고 그것으로 소형 모델을 SFT하는 방식이 증류의 변형으로 널리 쓰인다. 빠르고 저렴한 모델이 필요한 곳(분류, 라우팅, 간단한 요약)에 대형 모델의 능력 일부를 이식하는 수단이다.

== 병합: 학습 없이 능력 합치기

병합(merging)은 같은 베이스에서 갈라져 나온 여러 미세조정 모델의 가중치를 산술적으로 합성하는 기법이다. 수학 특화 모델과 코딩 특화 모델의 가중치를 평균 내서 둘 다 하는 모델을 만드는 식이다. 단순 평균부터, 미세조정으로 변한 부분만 선별해 합치는 TIES, 변화량을 무작위로 솎아 내는 DARE, 구면 보간을 쓰는 SLERP까지 여러 알고리즘이 있다.

학습이 전혀 필요 없다는 것이 매력이다. GPU 없이 가중치 파일 연산만으로 새 모델이 나온다. 오픈 모델 커뮤니티에서 리더보드 상위권 모델 상당수가 병합으로 만들어질 정도로 실용성이 검증되어 있다.

== 규모의 감각

지금까지의 기법들은 필요한 데이터와 비용의 자릿수가 서로 다르다. 어떤 기법을 검토할 때 먼저 확인할 것은 정밀한 견적이 아니라 자릿수다.

[cols="1,2,2"]
|===
| 기법 | 데이터 규모 | 계산 비용

| 사전학습
| 수조 토큰
| GPU 수천 장으로 수 주에서 수개월. 프런티어 모델은 수백억 원 이상

| 연속 사전학습
| 수십억~수천억 토큰
| GPU 수십~수백 장으로 수일에서 수 주

| SFT
| 수천~수십만 페어
| GPU 몇 장으로 몇 시간에서 며칠

| 선호 학습
| 수만~수십만 건의 비교 데이터
| SFT와 비슷한 자릿수

| LoRA(3장에서 다룬다)
| SFT와 같음
| 소비자용 GPU 한 장으로 몇 시간
|===

이 표에서 두 가지를 읽을 수 있다. 첫째, "모델을 학습시킨다"는 말은 자릿수가 대여섯 단계 차이 나는 작업들을 뭉뚱그린 표현이다. 사전학습은 소수 기업의 일이지만 SFT와 LoRA는 팀 단위로 실행할 수 있는 일이므로, "파인튜닝은 비싸다"는 통념은 어느 기법을 말하는지 확인하기 전에는 판단할 수 없다. 둘째, 병목은 GPU보다 데이터인 경우가 많다. SFT 페어 수만 건, 선호 비교 수만 건을 필요한 품질로 만드는 비용이 계산 비용을 넘어서기 쉽다. 그래서 실무의 질문은 "학습할 수 있는가"가 아니라 "이 품질의 데이터를 이 규모로 만들 수 있는가"가 된다.

== 모델 레이어의 공통 특성

여기까지의 기법들은 규모와 목적이 제각각이지만 공통 특성이 있다.

정보는 분산 표현으로 저장된다::
어느 파라미터가 어느 지식을 담는지 특정할 수 없다. 그래서 넣은 정보를 선택적으로 삭제하거나 열람할 수 없고, 무엇이 학습되었는지는 출력을 관찰해서 간접적으로만 확인할 수 있다.

적용은 영구적이고 전역적이다::
한번 학습된 정보는 모든 요청에 적용된다. 요청마다 켜고 끌 수 없다.

비용은 학습 시점에 든다::
데이터 준비와 GPU 학습 비용을 먼저 치르고, 추론 시점에는 추가 비용이 없다. 같은 정보를 매 요청의 프롬프트에 넣는 방식과 비용 구조가 반대다.

최신성이 없다::
학습 마감 이후의 정보는 없다. 정보를 갱신하려면 다시 학습해야 한다.

이 특성들의 반대편에 있는 것이 다음 장의 프롬프트 레이어다. 즉시 바꿀 수 있고, 요청 단위로 적용되고, 추론 시점에 비용이 드는 방식이다.
